## Why it's different

<div class="mlx-features">
  <div class="mlx-feature">
    <p class="lbl">Runtime</p>
    <h3>No Python</h3>
    <p>Bun calls <code>mlx-c</code> through <code>bun:ffi</code>. Run inference inside a Bun app or use the self-contained executable.</p>
  </div>
  <div class="mlx-feature">
    <p class="lbl">Correctness</p>
    <h3>Bit-exact</h3>
    <p>Forward-pass comparisons against pinned mlx-lm and mlx-optiq oracles. Each cache scheme and execution mode has a documented numerical contract.</p>
  </div>
  <div class="mlx-feature">
    <p class="lbl">Speed</p>
    <h3>Reuse computed work</h3>
    <p>Shared execution, speculative methods, specialized kernels, and RAM/SSD cache reuse. See the measured comparisons for each workload.</p>
  </div>
  <div class="mlx-feature">
    <p class="lbl">Protocols</p>
    <h3>Use familiar APIs</h3>
    <p>OpenAI chat completions, Anthropic Messages, and OpenAI Responses, with supported fields and compatibility settings documented in the API reference.</p>
  </div>
  <div class="mlx-feature">
    <p class="lbl">Multimodal</p>
    <h3>Tools &amp; vision</h3>
    <p>Native tool-calling parsed into OpenAI <code>tool_calls</code>; image input via native OS codecs (HEIC, AVIF, WebP…) on vision models.</p>
  </div>
  <div class="mlx-feature">
    <p class="lbl">Shape</p>
    <h3>Library-first</h3>
    <p>The server is one consumer of a TypeScript API. Import generation into a Bun process, or embed the binary as a Mac-app sidecar.</p>
  </div>
  <div class="mlx-feature">
    <p class="lbl">Memory</p>
    <h3>Personal memory</h3>
    <p>A local, git-tracked Markdown wiki your assistant can read for durable context. Inspect and edit it in your preferred editor.</p>
  </div>
  <div class="mlx-feature">
    <p class="lbl">The lab</p>
    <h3>An open playground</h3>
    <p>LoRA/ORPO fine-tuning on your Mac, speculative decoding research, and an interactive sampling-curve designer at <code>/curves</code>.</p>
  </div>
</div>

## Inspect the evidence

The [benchmark ledger](/reference/benchmarks/) records results on M1 Max and
M4 Pro, including default batching, context growth, and SSD cache reuse.
Each comparison identifies its model, settings, and machine conditions.
Remaining regressions and unsupported combinations are recorded alongside
successful results.

MLX, mlx-c, mlx-lm, and mlx-optiq provide the runtime foundations and numerical
references. Read [how mlx-bun uses them](/about/comparison/) and the
[correctness contract](/about/correctness/).
