<div class="lp-section-head">

## What you install

One command downloads models, serves them, generates, quantizes, trains and transcribes. The map above is the whole product.

</div>
<div class="lp-section-body">
<ul class="lp-list not-content">
<li id="what-engine">
<h3>Inference engine</h3>
<p>Runs the model graph on the GPU through MLX and Metal. The Neural Engine programs a model uses are compiled by the installer, or before the first model load that needs them. Validated configurations reproduce mlx-lm's logits bit for bit.</p>
</li>
<li id="what-server">
<h3>Local server</h3>
<p>Chat and text completions, Anthropic Messages, OpenAI Responses, embeddings, audio transcription and decisions on <code>localhost:8080</code>, over one continuous batching scheduler with paged and quantized KV caches, speculative decoding and runtime LoRA adapters. Every route is in the <a href="/reference/server-api/">HTTP API reference</a>.</p>
</li>
<li id="what-app">
<h3>Browser app</h3>
<p>Chat with tools and saved sessions, manage and download models, transcribe audio, quantize checkpoints, train adapters, generate datasets, and watch metrics and benchmarks. It opens when the server starts.</p>
</li>
<li id="what-libraries">
<h3>Libraries</h3>
<p><code>@mlx-bun/mlx</code>, <code>inference</code>, <code>quantize</code>, <code>training</code> and <code>hub</code> on npm: loading and generation, plus the kernels, layers, graphs, state, sampling and training they compose. Start with the <a href="/guides/library/">library guide</a>.</p>
</li>
<li id="what-cli">
<h3>Terminal</h3>
<p><code>get</code>, <code>serve</code>, <code>generate</code>, <code>embed</code>, <code>convert</code>, <code>train</code>, <code>fuse</code>, <code>transcribe</code> and <code>fit</code>. Every command and flag is in the <a href="/reference/cli/">CLI reference</a>, generated from the source.</p>
</li>
</ul>
</div>
</section>

<section class="lp-section" id="install">
<div class="lp-section-head">

## Install

Requires an Apple Silicon Mac running macOS 14 or later. Every option provides the `mlx-bun` command.

</div>
<div class="lp-section-body">

<Tabs>
<TabItem label="Installer">

```sh
curl -fsSL https://mlx-bun.dev/install.sh | sh
```

Downloads the signed, notarized bundle with its runtime and native libraries, then compiles the Neural Engine programs your Mac's models use. See the [installer options](/getting-started/installation/#standalone-bundle).

</TabItem>
<TabItem label="Homebrew">

```sh
brew install joshuarossi/tap/mlx-bun
```

Installs the same bundle and links the command. The app compiles the Neural Engine programs it lacks before the first model load. See the [Homebrew notes](/getting-started/installation/#homebrew).

</TabItem>
<TabItem label="npm">

```sh
bun install -g mlx-bun   # or run once: bunx mlx-bun
```

Requires Bun 1.4.2 or later; use Bun rather than Node's `npx`. See the [npm notes](/getting-started/installation/#npm-package).

</TabItem>
</Tabs>

<Steps>

1. **Serve a model.** Download one from Hugging Face and serve it, or run `mlx-bun` with no arguments to serve a cached model, downloading a starter on first run.

   ```sh
   mlx-bun get mlx-community/gemma-4-e4b-it-OptiQ-4bit
   mlx-bun serve e4b
   ```

2. **Send a request.** The browser app opens on port 8080, and the API answers beside it.

   ```sh
   curl http://localhost:8080/v1/chat/completions \
     -H 'Content-Type: application/json' \
     -d '{"messages": [{"role": "user", "content": "Hello!"}], "max_tokens": 128}'
   ```

3. **Or generate once, without a server.**

   ```sh
   mlx-bun generate e4b "Write a haiku about Apple Silicon."
   ```

</Steps>

The [quickstart](/getting-started/quickstart/) continues from here.

</div>
</section>

<section class="lp-section" id="why">
<div class="lp-section-head">

## Why mlx-bun

Built to be trusted first, then embedded.

</div>
<div class="lp-section-body">
<ul class="lp-list not-content">
<li>
<h3>Bit-exact numerics</h3>
<p>Validated configurations reproduce mlx-lm's logits bit for bit, and mlx-optiq's for mixed-precision KV. Correctness is a <a href="/about/correctness/">published contract</a> with evidence, not a benchmark table.</p>
</li>
<li>
<h3>Native on your Mac</h3>
<p>Metal does the math. The standalone bundle is signed, notarized and ships its own runtime, so there is no Python environment to manage and no API key to keep.</p>
</li>
<li>
<h3>Nothing to rewrite</h3>
<p>Chat Completions, Messages, Responses, embeddings and transcription keep their wire formats. Existing agents, tools and SDK code keep working after changing one URL.</p>
</li>
<li>
<h3>Composable</h3>
<p>Every layer is a public subpath: kernels, layers, graphs, caches, sampling, generation. The caller owns weights and state, and <code>using</code> disposes them. The whole server embeds with <code>mlx-bun/server</code>.</p>
</li>
<li>
<h3>Memory aware</h3>
<p>Fit estimates before a model loads, residency by memory budget across models, paged and quantized KV, prompt caches that persist to SSD, and continuous batching for every request.</p>
</li>
<li>
<h3>Private by default</h3>
<p>Downloaded models stay in the Hugging Face cache on your Mac; converted models, adapters, chats and KV state live under <code>~/.mlx-bun</code>. Nothing leaves your Mac unless you fetch or upload something yourself.</p>
</li>
</ul>
</div>
</section>

<section class="lp-section" id="decisions">
<div class="lp-section-head">

## Decisions, scored on your Mac

Use Jev or OpenAI Decisions-compatible endpoints with any supported local language model, sharing the same loaded weights as generation.

</div>
<div class="lp-section-body">

`POST /v1/decisions` accepts OpenAI's Decisions request. `POST /v1/systemone` accepts the System One format of [Jev](https://typesafe.ai), TypeSafe AI's decision model. Ask predicate questions (yes or no; Jev calls them noul), choice questions and score questions about text, or about an image with a vision model, and get the answer, a probability for every option and a confidence.

Every answer is scored from the loaded model's own likelihood of that answer. No token is sampled and nothing needs tuning. Keep the OpenAI or TypeSafe SDK and change `baseURL`; name a model that `GET /v1/models` lists with `capabilities.decisions`.

<Tabs>
<TabItem label="OpenAI">

```ts wrap
import OpenAI from "openai";

const openai = new OpenAI({ apiKey: "local", baseURL: "http://localhost:8080/v1" });

const { answers } = await openai.decisions.create({
  model: "mlx-community/gemma-4-e4b-it-OptiQ-4bit",
  input: "I was charged twice for my order.",
  questions: [{
    type: "choice", name: "department",
    instructions: "Which department should handle this complaint?",
    choices: [
      { value: "billing", description: "Payments, invoices, and refunds." },
      { value: "technical", description: "Problems using the product." },
      { value: "shipping", description: "Delivery and tracking." },
    ],
  }],
});
```

</TabItem>
<TabItem label="TypeSafe">

```ts wrap
import { TypeSafeClient, choice } from "@typesafe-ai/sdk";

const jev = new TypeSafeClient({ apiKey: "local", baseURL: "http://localhost:8080" });

const result = await jev.systemOne({
  model: "mlx-community/gemma-4-e4b-it-OptiQ-4bit",
  state: { document: "I was charged twice. Please fix this ASAP." },
  questions: {
    category: choice("What is this ticket about?", { billing: null, technical: null, other: null }),
  },
});
```

</TabItem>
<TabItem label="HTTP">

```sh wrap
curl http://localhost:8080/v1/decisions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "mlx-community/gemma-4-e4b-it-OptiQ-4bit",
    "input": "I was charged twice for my order. Please refund the duplicate payment.",
    "questions": [
      { "name": "refund", "type": "predicate", "instructions": "Does the customer ask for a refund?" },
      { "name": "severity", "type": "score", "instructions": "How severe is the problem?",
        "levels": [{ "label": "Minor inconvenience" }, { "label": "Customer payment problem" },
                   { "label": "Service completely unavailable" }] }
    ]
  }'
```

```sh wrap
curl http://localhost:8080/v1/systemone \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "mlx-community/gemma-4-e4b-it-OptiQ-4bit",
    "state": "I was charged twice for my order. Please refund the duplicate payment.",
    "questions": {
      "refund": { "type": "noul", "instructions": "Does the customer ask for a refund?" },
      "severity": { "type": "score", "instructions": "How severe is the problem?",
        "criteria": ["Minor inconvenience", "Customer payment problem", "Service completely unavailable"] }
    }
  }'
```

</TabItem>
<TabItem label="Answers">

```ts wrap
// One answer per question. OpenAI returns them in order; Jev keys them by name.
{ type: "predicate", name, probability }
{ type: "choice", name, choice, confidence, probabilities: [{ value, probability }] }
{ type: "score", name, score, confidence, probabilities: [{ value, label, probability }] }
```

Probabilities are a softmax over the candidates' average answer-token log likelihood; confidence follows Jev's documented formulas. The response names the model that ran and counts the tokens scored.

</TabItem>
</Tabs>

The [HTTP example](https://github.com/joshuarossi/mlx-bun/blob/main/apps/mlx-bun/scripts/decision-example.ts) and the [SDK examples](https://github.com/joshuarossi/mlx-bun/blob/main/apps/mlx-bun/scripts/decision-website-examples.mjs) run against a local server; the [HTTP API reference](/reference/server-api/) lists both routes.

## Build with the libraries

The `@mlx-bun/` packages are TypeScript on npm. They run on Bun 1.4.2 or later, with their native libraries inside the archives.

</div>
<div class="lp-section-body">

```sh
bun add @mlx-bun/inference
```

<Tabs>
<TabItem label="Generate">

<Code lang="ts" wrap code={exampleBody(generateSource, 'packages/inference/examples/qwen3-generate.ts')} title="packages/inference/examples/qwen3-generate.ts" />

The tested [example](https://github.com/joshuarossi/mlx-bun/blob/main/packages/inference/examples/qwen3-generate.ts) from the inference package, rendered from its source at build time. The caller owns the model, the inputs and every resource's lifetime.

</TabItem>
<TabItem label="Arrays">

<Code lang="ts" wrap code={exampleBody(arraysSource, 'packages/mlx/examples/arrays.ts')} title="packages/mlx/examples/arrays.ts" />

The MLX bindings own native memory explicitly: `using` disposes an array at the end of its scope. Tested [example](https://github.com/joshuarossi/mlx-bun/blob/main/packages/mlx/examples/arrays.ts).

</TabItem>
<TabItem label="Embed the server">

The server entry ships in the app package, not in `@mlx-bun/inference`:

```sh
bun add mlx-bun
```

```ts wrap
import { createServer, loadContext } from "mlx-bun/server";

const context = await loadContext("/path/to/hf-snapshot", "my-model");
const server = await createServer(context, 8080, { hostname: "127.0.0.1", memoryBudgetBytes: 12e9 });
try {
  console.log(`API http://127.0.0.1:${server.port}/v1`);
} finally {
  const { stopped, durability } = await server.close();
  if (stopped) context.dispose();
  if (!durability.durable) console.warn("cache persistence incomplete", durability);
}
```

The full app in your process: every HTTP route, the browser app, chat, jobs and the hub, over a model you loaded. It parses no arguments, installs no signal handler and downloads nothing. See the [server entry](https://github.com/joshuarossi/mlx-bun/blob/main/apps/mlx-bun/README.md#server-entry-mlx-bunserver).

</TabItem>
</Tabs>

<div class="lp-section-head">

## Models it runs

Download any of them from Hugging Face with `mlx-bun get`. Compatibility claims apply to <a href="/about/correctness/">named artifacts and configurations</a>.

</div>
<div class="lp-section-body">
<dl class="lp-models not-content">
<dt>Targeted graphs</dt>
<dd>Gemma 4, DiffusionGemma, GLM 5.2, Qwen 3, Qwen 3.5, Qwen 3 MoE, MiniCPM 5, Whisper and MOSS-Image (text-to-image).</dd>
<dt>Generic dense graph</dt>
<dd>The architectures mlx-lm's universal path knows: Llama, Mistral, SmolLM 3, Qwen 2, Gemma, Gemma 2, Phi 3, OLMo 2, GLM 4, Granite and StarCoder 2.</dd>
</dl>

### Our quant on Hugging Face

We publish [Qwen3.8-27B-Trellis-3.2bpw](https://huggingface.co/mlx-bun/Qwen3.8-27B-Trellis-3.2bpw), a 27B Qwen model in mlx-bun's packed Trellis format. The full download is about **12.25 GB**; running it needs additional memory for inference. This is an optional larger model, separate from the first-run starter. See the model card for requirements, evaluations and usage.
