<p class="lp-eyebrow">What it is</p>

## One install. Every surface.

<p class="lp-lead">One command downloads models, serves them, generates, quantizes, trains and transcribes. The same install gives you a local API, a browser app, and the libraries underneath.</p>

<div class="lp-bento not-content">
<article class="lp-tile lp-tile-wide">
<div class="lp-tile-icon"><Icon name="server" /></div>
<h3>A local server for the SDKs you already use</h3>
<p>Point the OpenAI or Anthropic SDK at <code>localhost:8080</code>. Every request runs on one continuous batching scheduler, with paged and quantized KV caches, speculative decoding and runtime LoRA adapters when you want them.</p>
<ul class="lp-endpoints">
<li>/v1/chat/completions</li><li>/v1/completions</li><li>/v1/messages</li><li>/v1/responses</li><li>/v1/embeddings</li><li>/v1/audio/transcriptions</li><li>/v1/decisions</li><li>/v1/systemone</li><li>/v1/models</li>

</article>

<div class="lp-section" id="why">

<p class="lp-eyebrow">Why mlx-bun</p>

## Built to be trusted, then embedded.

<div class="lp-grid lp-grid-3 lp-reasons not-content">
<article class="lp-reason">
<div class="lp-tile-icon"><Icon name="approve-check" /></div>
<h3>Bit-exact numerics</h3>
<p>Validated configurations reproduce mlx-lm's logits bit for bit, and mlx-optiq's for mixed-precision KV. Correctness is a <a href="/about/correctness/">published contract</a> with evidence, not a benchmark table.</p>
</article>
<article class="lp-reason">
<div class="lp-tile-icon"><Icon name="apple" /></div>
<h3>Native on your Mac</h3>
<p>Metal does the math, and the Neural Engine programs your models use are compiled at install. The standalone bundle is signed, notarized and ships its own runtime. No Python, no API key.</p>
</article>
<article class="lp-reason">
<div class="lp-tile-icon"><Icon name="random" /></div>
<h3>Drop-in compatible</h3>
<p>Chat Completions, Messages, Responses, embeddings and transcription keep their wire formats, so existing SDKs, agents and tools work by changing one URL.</p>
</article>
<article class="lp-reason">
<div class="lp-tile-icon"><Icon name="analytics" /></div>
<h3>Decisions, locally</h3>
<p>A drop-in for OpenAI's Decisions API and Jev's System One format: typed answers with probabilities and confidence, scored on the same resident weights that serve chat. <a href="#decisions">See how</a>.</p>
</article>
<article class="lp-reason">
<div class="lp-tile-icon"><Icon name="puzzle" /></div>
<h3>Composable by design</h3>
<p>Every layer is a public subpath: kernels, layers, graphs, caches, sampling, generation. The caller owns weights and state, and <code>using</code> disposes them. Embed the whole server with <code>mlx-bun/server</code>.</p>
</article>
<article class="lp-reason">
<div class="lp-tile-icon"><Icon name="database" /></div>
<h3>Memory aware</h3>
<p>Fit estimates before a model loads, residency by memory budget across models, paged and quantized KV, prompt caches that persist to SSD, and continuous batching for every request.</p>
</article>
</div>

<p class="lp-eyebrow">Decisions API</p>

## Decisions, scored on your Mac.

`POST /v1/decisions` is a drop-in replacement for OpenAI's Decisions API, and `POST /v1/systemone` speaks Jev's System One format from TypeSafe AI. Ask predicate, choice and score questions about any text, or an image with a vision model, and get back the answer, a probability for every option, and a confidence.

Every answer is scored from the loaded model's own likelihood of that answer. No token is sampled, nothing needs tuning or calibration, and the same resident weights keep serving chat.

<ul class="lp-checks">
<li>**Keep your SDK.** Change `baseURL` in the OpenAI or TypeSafe client and the rest of your code stays.</li>
<li>**Three question types.** Predicate (noul), choice and score, with OpenAI's ordered answers or Jev's keyed map.</li>
<li>**Text and images.** OpenAI `input_image` parts and Jev's base64 or multipart assets, on models with vision.</li>
<li>**Any local model.** Name the model from `GET /v1/models`; the host loads it and shares it with generation.</li>
</ul>

<TabItem label="Answers" icon="list-format">

```ts
// One answer per question. OpenAI returns them in order; Jev keys them by name.
{ type: "predicate", name, probability }
{ type: "choice", name, choice, confidence, probabilities: [{ value, probability }] }
{ type: "score", name, score, confidence, probabilities: [{ value, label, probability }] }
```

Probabilities are a softmax over the candidates' average answer-token log likelihood; confidence follows Jev's documented formulas. The response names the model that actually ran and counts the tokens scored.

<p class="lp-eyebrow">How to install</p>

## Install in one line.

<p class="lp-lead">Requires an Apple Silicon Mac running macOS 14 or later. Every option provides the `mlx-bun` command; the installer and npm package also add mlx-lm's commands under mlx-bun's names.</p>

<Tabs>
<TabItem label="Installer" icon="apple">

```sh
curl -fsSL https://mlx-bun.dev/install.sh | sh
```

Downloads the signed, notarized bundle with its runtime and native libraries, then compiles the Neural Engine programs your Mac's models use so no model load or prompt has to. See the [installer options](/getting-started/installation/#standalone-bundle).

</TabItem>
<TabItem label="Homebrew" icon="homebrew">

```sh
brew install joshuarossi/tap/mlx-bun
```

Installs the same bundle and links the command. The app checks the Neural Engine programs before every model load and compiles only what the cache lacks. See the [Homebrew notes](/getting-started/installation/#homebrew).

</TabItem>
<TabItem label="npm" icon="bun">

```sh
bun install -g mlx-bun   # or run once: bunx mlx-bun
```

Requires Bun 1.4.2 or later; use Bun rather than Node's `npx`. See the [npm notes](/getting-started/installation/#npm-package).

</TabItem>
</Tabs>

<Steps>

1. **Serve a model.** Download one from Hugging Face and serve it, or run `mlx-bun` with no arguments to serve a cached model, downloading a starter on first run.

   ```sh
   mlx-bun get mlx-community/gemma-4-e4b-it-OptiQ-4bit
   mlx-bun serve e4b
   ```

2. **Send a request.** The browser app opens on port 8080, and the API answers beside it.

   ```sh
   curl http://localhost:8080/v1/chat/completions \
     -H 'Content-Type: application/json' \
     -d '{"messages": [{"role": "user", "content": "Hello!"}], "max_tokens": 128}'
   ```

3. **Or generate once, without a server.**

   ```sh
   mlx-bun generate e4b "Write a haiku about Apple Silicon."
   ```

</Steps>

<p class="lp-eyebrow">How to import</p>

## Build with the libraries.

<p class="lp-lead">The `@mlx-bun/` packages are TypeScript, published to npm, and run on Bun 1.4.2 or later with their native libraries inside the archives. The caller owns the model, the inputs, and every resource's lifetime.</p>

```sh
bun add @mlx-bun/inference
```

<TabItem label="Arrays" icon="seti:typescript">

<Code lang="ts" code={exampleBody(arraysSource, 'packages/mlx/examples/arrays.ts')} title="packages/mlx/examples/arrays.ts" />

The MLX bindings own native memory explicitly: `using` disposes an array at the end of its scope. Tested [example](https://github.com/joshuarossi/mlx-bun/blob/main/packages/mlx/examples/arrays.ts).

</TabItem>
<TabItem label="Embed the server" icon="server">

```ts
import { createServer, loadContext } from "mlx-bun/server";

const context = await loadContext("/path/to/hf-snapshot", "my-model");
const server = await createServer(context, 8080, { hostname: "127.0.0.1", memoryBudgetBytes: 12e9 });
try {
  console.log(`API http://127.0.0.1:${server.port}/v1`);
} finally {
  const { stopped, durability } = await server.close();
  if (stopped) context.dispose();
  if (!durability.durable) console.warn("cache persistence incomplete", durability);
}
```

The full app in your process: every HTTP route, the browser app, chat, jobs and the hub, over a model you loaded. It parses no arguments, installs no signal handler and downloads nothing. See the [server entry](https://github.com/joshuarossi/mlx-bun/blob/main/apps/mlx-bun/README.md#server-entry-mlx-bunserver).

</TabItem>
</Tabs>
